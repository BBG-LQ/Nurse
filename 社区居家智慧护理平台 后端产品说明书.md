## 社区居家智慧护理平台 — API 与 Proto 文件完整设计

本文件给出 6 个微服务下**每一个** `.api` 子文件与 `.proto` 文件的完整内容，并附上「API logic → RPC 方法」的调用映射表。所有 `.api` 采用 go-zero-looklook 风格：主 api 只做 `import` + `@server(prefix)` 声明，子 api 携带 `type` 与路由。

## 0. 总览

| 服务 | 主 api | 子 api 文件 | proto | API 端口 | RPC 端口 |
|---|---|---|---|---|---|
| usercenter | `desc/usercenter.api` | `auth/auth.api`、`user/user.api` | `pb/usercenter.proto` | 8881 | 9881 |
| elderly | `desc/elderly.api` | `archive/archive.api`、`medication/medication.api` | `pb/elderly.proto` | 8882 | 9882 |
| nurse | `desc/nurse.api` | `profile/profile.api`、`training/training.api` | `pb/nurse.proto` | 8883 | 9883 |
| vital | `desc/vital.api` | `ingest/ingest.api`、`query/query.api` | `pb/vital.proto` | 8884 | 9884 |
| order | `desc/order.api` | `dispatch/dispatch.api`、`service/service.api` | `pb/order.proto` | 8885 | 9885 |
| alert | `desc/alert.api` | `safety/safety.api`、`adverse/adverse.api` | `pb/alert.proto` | 8886 | 9886 |

**全局约定**
- HTTP 前缀统一 `/api/v1`，在**主 api** 的 `@server(prefix: /api/v1)` 中声明。
- 子 api 的 `@server(group: xxx)` 仅用于分组，不重复声明 prefix。
- 所有子 api 的 `service` 名称必须与主 api 一致（如 `usercenter-api`），goctl 合并。
- 路径参数用 `path:"id"`，查询参数用 `form:"..."`，请求体默认 `json`。
- proto 字段全部 `snake_case`；时间统一用 `string`（`YYYY-MM-DD HH:mm:ss`），本地验证不做 `google.protobuf.Timestamp` 映射。
- proto 中每个方法都对应 API logic 的一次调用，或跨服务 RPC 依赖。

syntax = "proto3";
package usercenter;
option go_package = "./usercenter";

service usercenter {
  rpc Login             (LoginReq)             returns (LoginResp);
  rpc GetUser           (GetUserReq)           returns (GetUserResp);
  rpc BindFamily        (BindFamilyReq)        returns (BindFamilyResp);
  rpc ListFamilyElders  (ListFamilyEldersReq)  returns (ListFamilyEldersResp);
  rpc UpdateProfile     (UpdateProfileReq)     returns (UpdateProfileResp);
}

message LoginReq {
  string mobile   = 1;
  string password = 2;
}
message LoginResp {
  string token   = 1;
  string role    = 2;
  int64  user_id = 3;
}

message GetUserReq  { int64 user_id = 1; }
message GetUserResp {
  int64  id        = 1;
  string mobile    = 2;
  string real_name = 3;
  string role      = 4;
  int32  status    = 5;
}

message BindFamilyReq {
  int64  family_user_id = 1;
  int64  elderly_id     = 2;
  string relation       = 3;
}
message BindFamilyResp { bool ok = 1; }

message ListFamilyEldersReq  { int64 family_user_id = 1; }
message ListFamilyEldersResp { repeated int64 elderly_ids = 1; }

message UpdateProfileReq {
  int64  user_id   = 1;
  string real_name = 2;
}
message UpdateProfileResp { bool ok = 1; }

    group: adverse
